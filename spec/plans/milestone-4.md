# Plan – Milestone 4: שגיאות, מצבי קצה ובדיקת התאמה

## 1. מטרה והיקף

לוודא שהאתר מתנהג נכון גם כשקובץ לא נטען, כשלוחצים מהר, וכשהתוכן ארוך או רחב – ולסגור פערים קטנים מול PRD, ARCHITECTURE ו-DESIGN. אבן הדרך הזו היא בעיקר **בדיקה ותיקון**, ורק מעט קוד חדש.

**בפנים:** השלמת מסך שגיאת הטעינה לפי ה-Wireframe; חיזוק עמידות התצוגה לתוכן רחב; נגישות בסיסית; סדרת בדיקות למצבי קצה; רשימת בדיקה ידנית ל-Chrome ול-Edge.

**בחוץ:** פריסה ל-GitHub Pages (Milestone 5). אין פיצ'רים חדשים.

## 2. מה כבר קיים ועונה על הדרישות

בדיקת הקוד הנוכחי מול דרישות אבן הדרך:

| דרישה | מצב |
|---|---|
| תוכן ישן לא מוצג תחת פרומפט חדש | **קיים מעצם המבנה.** התוכן המוצג נגזר תמיד מ-`sources[language][selectedId]`; כל קובץ נשמר תחת השפה והפרומפט שלו, ולכן תשובה מאוחרת לא יכולה לדרוס בחירה אחרת |
| שאר הלחצנים פעילים אחרי כשל | קיים – לכל קובץ סטטוס נפרד |
| תוצאת העתקה ישנה לא מקפיצה הודעה | קיים – מונה הניסיונות (`attemptRef`) מתקדם בכל בחירה ובכל החלפת שפה |
| כשל Clipboard לא מונע קריאה והעתקה ידנית | קיים |
| הדף כולו נגלל, בלי Scroll פנימי ובלי Sticky | קיים |
| הודעות בשפה הפעילה | קיים |

לכן אין צורך ב-`AbortController` או במזהי בקשות נוספים: הבעיה שהם פותרים לא קיימת במבנה הזה. הבדיקות בסעיף 6 יאמתו זאת בפועל, ואם בדיקה תיכשל – מתקנים במסגרת אבן הדרך.

## 3. מה חסר – שינויים בקוד

1. **מסך שגיאת הטעינה לפי ה-Wireframe:** כיום מוצגים אייקון ומשפט. ב-Wireframe יש גם כותרת („Error”). מוסיפים כותרת – „שגיאה” / „Error” – מעל המשפט הקיים, בגודל H2 (`24px/700`), עם אייקון ההתראה בצבע ניטרלי.
2. **תוכן רחב לא שובר את הדף:** שבעת הפרומפטים הנוכחיים אינם כוללים טבלאות או בלוקי קוד, אבל ה-PRD דורש שהם יוצגו נכון. מוודאים שטבלה רחבה, כתובת ארוכה או מילה ארוכה נשברות בתוך אזור התוכן ולא יוצרות גלילה אופקית של הדף (`table-layout`, `overflow-wrap: anywhere` במקומות הנדרשים). השינוי בפועל ייקבע לפי תוצאת הבדיקה.
3. **סדר Tab תואם לסדר החזותי בלחצני השפה:** כיום בממשק האנגלי „עברית” מוצג מימין באמצעות היפוך ב-CSS, ולכן מקש Tab עובר מימין לשמאל. מחליפים את ההיפוך ב-CSS בסדר רינדור לפי שפה, כך שהמראה זהה אבל Tab נע בכיוון הקריאה. „עברית” נשאר תמיד מימין ל-„English”.
4. **אנימציית ה-Toast מכבדת „הפחתת תנועה”:** למשתמש שהגדיר במערכת ההפעלה `prefers-reduced-motion`, ה-Toast מופיע ונעלם בלי תנועה. משכי ההצגה (2 ו-5 שניות) לא משתנים.
5. **שם נגיש לאזור התוכן:** `aria-label` ל-`<section>` של התצוגה („תצוגת הפרומפט” / “Prompt view”), כדי שקורא מסך יזהה את האזור.

**לא כלול (החלטה):** ניסיון טעינה חוזר אוטומטי לקובץ שנכשל. קובץ שלא נטען נשאר במצב שגיאה עד רענון הדף. ה-PRD דורש הודעת שגיאה ושהלחצנים האחרים ימשיכו לפעול, ולא מנגנון ניסיון חוזר.

## 5. פירוט השינויים

### `i18n.ts`
| מפתח | עברית | English |
|---|---|---|
| `loadErrorTitle` | שגיאה | Error |
| `viewerLabel` | תצוגת הפרומפט | Prompt view |

### `PromptViewer.tsx`
- מצב שגיאה: `AlertIcon` (40px) ← `<h2>` עם `loadErrorTitle` ← `<p>` עם `loadError`. נשאר `role="alert"`.
- `aria-label={strings.viewerLabel}` על ה-`<section>` בכל המצבים.

### `LanguageToggle.tsx`
שני הלחצנים מוגדרים פעם אחת, ומרונדרים בסדר `[עברית, English]` בעברית ו-`[English, עברית]` באנגלית. ב-RTL הראשון מימין, ב-LTR השני מימין – כך „עברית” תמיד מימין.

### `styles.css`
- `.viewer.is-error h2 { margin: 0; font-size: 24px; font-weight: 700; }`
- הסרת הכלל `html[dir='ltr'] .language-toggle { flex-direction: row-reverse; }`.
- `@media (prefers-reduced-motion: reduce) { .toast { animation: none; } }`
- תוכן רחב – לפי הבדיקה: `overflow-wrap: anywhere` לתאי טבלה ולקישורים, ו-`table-layout: fixed` אם טבלה רחבה עדיין חורגת.

## 6. תוכנית הבדיקות

### שיטה
כדי לדמות קבצים חסרים, רשת איטית ותוכן מיוחד **בלי לגעת בקובצי הפרומפטים האמיתיים**, הבדיקות יחליפו בדפדפן את פונקציית `fetch` בגרסה נשלטת לפני שהאפליקציה עולה. כך אפשר להחזיר תשובת 404, לעכב תשובה ולשחרר אותה ברגע נבחר, או להחזיר Markdown לבדיקה (טבלאות, שורות ארוכות, טקסט מעורב). ההחלפה קיימת רק בזמן הבדיקה בדפדפן ואינה חלק מהקוד.

### בדיקות מול ה-Definition of Done

| תנאי | בדיקות |
|---|---|
| קובץ חסר או `fetch` שנכשל ← שגיאה בשפה המתאימה, בלי תוכן ישן, שאר הלחצנים פועלים | (א) תשובת 404 לקובץ אחד; (ב) `fetch` שנדחה (כשל רשת); (ג) תשובת HTML עם סטטוס 200, כמו שמחזיר שרת הפיתוח. בכל מקרה: בחירת פרומפט תקין ← בחירת הפרומפט הפגום ← מוצגת שגיאה עם כותרת, אין שריד מהפרומפט הקודם, אין Toast, ושאר ששת הלחצנים מציגים את התוכן שלהם. חוזרים על הבדיקה באנגלית, כולל מקרה שבו הקובץ פגום רק בשפה אחת |
| בחירה מהירה או החלפת שפה בזמן טעינה ← רק תוכן והודעות עדכניים | (א) כל התשובות מעוכבות: לוחצים A ואז B, משחררים את A אחרי B ← מוצג B בלבד; (ב) לוחצים A בזמן טעינה, מחליפים שפה, משחררים את התשובות ← מוצגת ההנחיה, אין פרומפט ואין Toast; (ג) לוחצים A בזמן טעינה ומחכים ← מוצג „טוען…”, ואחרי השחרור התוכן מופיע ומתבצע ניסיון העתקה אחד; (ד) רצף לחיצות מהיר על כל שבעת הלחצנים ← לחצן מודגש אחד, והתוכן שלו |
| כשל Clipboard לא מונע קריאה או העתקה ידנית; אין הצלחה מטעה | `writeText` שנדחה / חסר / מתעכב: הפרומפט ותיבת המקור מוצגים; Toast הצלחה אינו מופיע לפני סיום מוצלח; תוצאה של פרומפט קודם לא מופיעה אחרי בחירת פרומפט אחר או החלפת שפה |
| פרומפט ארוך נגלל עם הדף; אין Scroll פנימי או Sidebar מוצמד | בפרומפט הארוך ביותר בכל שפה: אין אלמנט בתוך אזור התוכן עם גלילה משלו; טור הלחצנים נגלל החוצה מהמסך; תיבת המקור בגובה מלא |
| קריאות Markdown, טבלאות וטקסט מעורב | Markdown לבדיקה עם טבלה רחבה, רשימות מקוננות, בלוק קוד עם שורה ארוכה, כתובת ארוכה, ופסקאות מעורבות עברית/אנגלית – בשתי השפות: אין גלילה אופקית של הדף, הטבלה בתוך המסגרת, שמות קבצים וקוד מוצגים בכיוון הנכון |
| נגישות בסיסית | מעבר ב-Tab על כל הלחצנים בסדר החזותי, טבעת Focus נראית, הפעלה ב-Enter וברווח; `aria-pressed` בלחצני השפה ו-`aria-current` בפרומפט הנבחר; ה-Toast ב-`role="status"` והשגיאה ב-`role="alert"`; ניגודיות טקסט מספקת |
| התאמה ל-PRD, ARCHITECTURE ו-DESIGN, בלי תוספות | מעבר סעיף-סעיף על FR-01 עד FR-06, מקרי הקצה שב-PRD וטבלת ההחלטות שב-ARCHITECTURE סעיף 9; השוואה חזותית של ארבעת מצבי ה-Wireframes; `npm run build` ובדיקת התוצר עם `npm run preview` |
| בדיקה ידנית ב-Chrome וב-Edge | **באחריות המשתמש** – ראו להלן |

### בדיקה ידנית ב-Chrome וב-Edge (המשתמש)
אין לי גישה להפעיל את Chrome ואת Edge שעל המחשב, ו-Clipboard אמיתי חסום בחלונית הדפדפן המובנית. בסיום הבנייה תימסר רשימת בדיקה קצרה לביצוע בכל אחד משני הדפדפנים: בחירה, תצוגה, העתקה אוטומטית והדבקה, העתקה ידנית מתיבת המקור, שתי השפות, שמירת שפה אחרי רענון, ומצב שגיאה (באמצעות שינוי שם זמני של קובץ אחד, או חסימת הכתובת שלו ב-DevTools).

## 7. סדר הבנייה

1. הרצת סדרת הבדיקות על הקוד הקיים, לפני שינויים, כדי לזהות מה באמת נכשל.
2. השינויים מסעיף 3, ותיקון כל מה שהבדיקות חשפו.
3. הרצה חוזרת של כל הבדיקות.
4. `npm run build` ו-`npm run preview`.
5. סימון ✅ ב-`MILESTONES.md` ומסירת רשימת הבדיקה הידנית.

אם בדיקה תחשוף בעיה שתיקונה דורש שינוי ב-PRD, ב-DESIGN או ב-ARCHITECTURE – עוצרים ושואלים.
