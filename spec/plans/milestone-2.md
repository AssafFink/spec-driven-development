# Plan – Milestone 2: העתקת Markdown אוטומטית וידנית

## 1. מטרה והיקף

כל לחיצה על לחצן פרומפט מנסה להעתיק ל-Clipboard את טקסט ה-Markdown המקורי ומציגה הודעה לפי התוצאה בפועל. בנוסף, אזור התוכן מציג את מקור ה-Markdown בתיבה לקריאה בלבד, שממנה אפשר לסמן ולהעתיק ידנית כל קטע.

**בפנים:** ניסיון העתקה בכל לחיצה (גם חוזרת), הודעת הצלחה/כישלון בעברית, תיבת מקור `textarea` לקריאה בלבד בלי גלילה פנימית.

**בחוץ:** אנגלית והחלפת שפה (Milestone 3); מסך שגיאת טעינה מלא ובדיקות Race Conditions מקיפות (Milestone 4).

## 2. מצב קיים שעליו בונים

- `App.tsx` כבר טוען את שבעת הקבצים לזיכרון בפתיחת הדף (`sources`), כך שבזמן לחיצה הטקסט בדרך כלל כבר זמין – וזה מה שמאפשר לקרוא ל-`writeText` ישירות מתוך הלחיצה.
- `PromptViewer.tsx` מציג הנחיה / טעינה / שגיאה / Markdown מרונדר.
- הטקסט נשמר כפי שהתקבל מ-`fetch`, בלי שינוי.

## 3. החלטות מימוש

1. **ההעתקה מתחילה בתוך ה-Click Handler, בלי `await` לפניה.** אם הטקסט כבר בזיכרון – קוראים ל-`navigator.clipboard.writeText(text)` מיד. הדפדפן דורש שהעתקה תיזום מפעולת משתמש, ולכן אסור שתקדם לה המתנה.
2. **לחיצה לפני שהקובץ סיים להיטען:** מסמנים „ממתין להעתקה” עבור הפרומפט הזה; כשהטקסט מגיע והפרומפט עדיין הנבחר – מנסים להעתיק. ייתכן שהדפדפן יחסום ניסיון כזה, ואז תוצג הודעת הכישלון עם ההנחיה הידנית. לא מבטיחים הצלחה במקרה הזה.
3. **הודעה רק לפי תוצאת ה-Promise.** עם הלחיצה מצב ההעתקה מתאפס (אין הודעה); הודעת הצלחה מוצגת רק אחרי ש-`writeText` הסתיים בהצלחה, והודעת כישלון אם נדחה, זרק שגיאה, או ש-`navigator.clipboard` אינו קיים.
4. **מניעת הודעה מיושנת:** מונה ניסיונות (`useRef`). תוצאה של ניסיון ישן שמגיעה אחרי לחיצה חדשה – מתעלמים ממנה. כך הודעה של פרומפט קודם לא תופיע על הנוכחי.
5. **קובץ שלא נטען:** לא מנסים להעתיק ולא מוצגת הודעת העתקה – רק הודעת שגיאת הטעינה הקיימת.
6. **תיבת המקור ממוקמת מתחת לתצוגה המעוצבת**, באותו אזור תוכן, מופרדת בקו דק ועם כותרת קטנה („מקור Markdown להעתקה ידנית”). התצוגה המעוצבת נשארת העיקר לקריאה, כמו ב-Wireframes וב-Mockups.
7. **בלי גלילה פנימית בתיבת המקור – באמצעות CSS בלבד:** `field-sizing: content` גורם ל-`textarea` לגדול לגובה התוכן שלה. התכונה נתמכת ב-Chrome וב-Edge, שהם הדפדפנים היחידים שהמוצר תומך בהם, ולכן אין צורך בקוד JavaScript למדידת גובה. בנוסף `resize: none`.
8. **הודעת הכישלון בצבעים ניטרליים, לא אדומים.** ב-Style Guide מופיעה דוגמת הודעה אדמדמה, אבל אין לה Color Token מוגדר, ו-DESIGN מורה לא להמציא צבעים. הכישלון יובחן מההצלחה באייקון התראה, במסגרת כהה (Charcoal) על רקע Light Gray ובנוסח – לא בצבע בלבד, כנדרש ב-DESIGN.
9. **לא נוגעים בטקסט המקור**, כולל סופי שורות. הערה: שבעת הקבצים שמורים כרגע עם סופי שורות של Windows; תיבת טקסט בדפדפן מציגה אותם כשורות רגילות, וזה לא משנה את התוכן המועתק בפועל.
10. **בלי כפתור „העתק” נפרד** – ה-PRD מגדיר שההעתקה נעשית בלחיצה על לחצן הפרומפט עצמו, ולחיצה חוזרת עליו מעתיקה שוב.

## 4. קבצים

**חדש:**
- `src/clipboard.ts` – `copyText(text): Promise<boolean>`. מחזיר `true` רק אם `writeText` הסתיים בהצלחה; `false` בכל מקרה אחר (אין API, דחייה, חריגה). הקריאה ל-`writeText` מתבצעת באופן סינכרוני בתחילת הפונקציה.

**משתנים:**
- `src/App.tsx` – מצב `copyStatus: 'idle' | 'success' | 'failure'`, מונה ניסיונות, סימון „ממתין להעתקה”, והרחבת `handleSelect`.
- `src/components/PromptViewer.tsx` – הודעת המשוב ותיבת המקור.
- `src/components/icons.tsx` – `CheckIcon` (עיגול עם ✓); `AlertIcon` יקבל גודל כפרמטר כדי לשמש גם בהודעה.
- `src/i18n.ts` – שלוש מחרוזות חדשות.
- `src/styles.css` – עיצוב ההודעה ותיבת המקור.
- `spec/MILESTONES.md` – סימון ✅ בסיום.

## 5. מבנה הקוד

### `App.tsx`

```
handleSelect(id):
  setSelectedId(id); window.scrollTo(0, 0)
  setCopyStatus('idle')
  attempt = ++attemptRef.current          // invalidates older attempts
  source = sources[id]
  if source is ready  -> startCopy(source.text, attempt)   // still inside the click
  else if not error   -> pendingCopyRef.current = id       // copy when it arrives
  else                -> pendingCopyRef.current = null

startCopy(text, attempt):
  copyText(text).then(ok => {
    if attempt === attemptRef.current -> setCopyStatus(ok ? 'success' : 'failure')
  })

useEffect on [selectedId, sources]:
  if pendingCopyRef.current === selectedId and its source is ready
    -> clear pending, startCopy(text, attemptRef.current)
  if its source is error -> clear pending
```

לחיצה חוזרת על אותו לחצן עוברת באותו מסלול, ולכן מבצעת ניסיון העתקה נוסף ומחזירה את הדף לתחילתו.

### `PromptViewer.tsx`
מקבל גם `copyStatus`. במצב `ready` מציג, בסדר הזה:

1. **הודעת משוב** – `<div role="status" aria-live="polite">` שנמצא תמיד ב-DOM (ריק כשאין הודעה), כדי שקוראי מסך יכריזו על השינוי. הצלחה: `CheckIcon` + טקסט. כישלון: `AlertIcon` + טקסט.
2. **Markdown מרונדר** – ללא שינוי.
3. **מקור להעתקה ידנית** – קו מפריד, כותרת קטנה (`<label>` המקושרת לתיבה), ו-`<textarea readOnly value={text} spellCheck={false}>`.

### `i18n.ts` – מחרוזות חדשות (עברית)
- `copySuccess`: „הפרומפט הועתק בהצלחה ל-Clipboard” (הנוסח שב-Mockups).
- `copyFailure`: „ההעתקה האוטומטית נכשלה. אפשר לסמן את הטקסט בתיבת המקור שבתחתית האזור ולהעתיק ידנית (Ctrl+C).”
- `sourceLabel`: „מקור Markdown להעתקה ידנית”.

## 6. עיצוב (`styles.css`)

- **הודעת משוב:** שורה בראש אזור התוכן, `display: inline-flex`, אייקון + טקסט בגודל Caption (`14px`), רדיוס `8px`, ריפוד `8px 16px`, מרווח `16px` מתחתיה. כשהיא ריקה – אינה תופסת מקום.
  - הצלחה: רקע Pale Green, מסגרת Technical Green.
  - כישלון: רקע Light Gray, מסגרת Charcoal, משקל `500`.
- **אזור המקור:** `margin-block-start: 32px`, קו עליון Greige, כותרת בגודל Caption בצבע Charcoal ומשקל `600`.
- **תיבת המקור:** רוחב מלא, `field-sizing: content`, `resize: none`, גופן monospace `14px`, גובה שורה `1.6`, רקע Paper White, מסגרת Greige, רדיוס `8px`, ריפוד `16px`, `white-space: pre-wrap`. כיווניות לפי שפת הדף (RTL בעברית). `:focus-visible` כמו בלחצנים.

## 8. בדיקה מול ה-Definition of Done

| תנאי | איך נבדק |
|---|---|
| ה-Clipboard מכיל את תוכן קובץ ה-`.md` כפי שהוא | לכידת הטקסט שנשלח ל-`writeText` והשוואה תו-בתו לתוכן שהתקבל מ-`fetch` של אותו קובץ, לכל שבעת הלחצנים; בנוסף הדבקה ידנית ב-Notepad על ידי המשתמש |
| לחיצה חוזרת מבצעת ניסיון נוסף | ספירת הקריאות ל-`writeText` בשתי לחיצות רצופות על אותו לחצן |
| הודעת הצלחה רק אחרי הצלחה בפועל; חסימה או שגיאה ← הודעת כישלון והנחיה ידנית | הדמיית `writeText` שנדחה, הדמיית `writeText` שמתעכב (אין הודעה עד לסיום), והדמיית היעדר `navigator.clipboard` |
| `Ctrl+C` מתיבת המקור – מלא וחלקי – זהה לתווים שנבחרו | השוואת ערך התיבה לטקסט המקור; סימון טווח חלקי והשוואתו לאותו טווח במקור; בדיקה ידנית של המשתמש עם `Ctrl+A`, `Ctrl+C` והדבקה |
| התצוגה זמינה גם בכישלון; אין גלילה פנימית בתיבת המקור | אחרי כישלון מדומה ה-Markdown והתיבה מוצגים; בתיבה `scrollHeight` שווה ל-`clientHeight` בפרומפט הארוך ביותר |
| הודעה מיושנת אינה מוצגת | לחיצה על פרומפט שני בזמן שההעתקה של הראשון מתעכבת – מוצגת רק תוצאת השני |

**מגבלת בדיקה ידועה:** חלונית הדפדפן המובנית כאן עשויה לחסום גישה ל-Clipboard, ואז תוצג בה הודעת הכישלון. את ההצלחה האמיתית המשתמש מאמת ב-Chrome או ב-Edge רגיל.
