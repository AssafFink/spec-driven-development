# MILESTONES – Spec-Driven Development Prompts

מסמך אבני הדרך לפיתוח האתר, בהתבסס על `PRD.md`, `ARCHITECTURE.md` ו-`DESIGN.md`.

הפרויקט הוא אתר Web סטטי בעל **דף אחד ל-Desktop בלבד**, המבוסס על React, TypeScript ו-Vite, עם שבעה פרומפטים בשתי שפות. אין Backend, Database או Login. ה-PRD מגדיר את ההתנהגות, ARCHITECTURE.md את המימוש הטכני ו-DESIGN.md את הממשק החזותי.

> **תלות בתוכן קיים:** נדרשים 14 קובצי Markdown מקוריים (שבעה בעברית ושבעה באנגלית). הם אינם כלולים בטקסט ה-PRD ואין לייצר או לשכתב את תוכנם. כאשר קובץ מקור אינו זמין, יש לדווח על החוסר; לא להציג תוכן מומצא כאילו הוא הקובץ המקורי. בדיקות שנשענות על תוכן הקבצים יושלמו כאשר הם יתקבלו.

## Milestone 1 – אתר עובד ובחירת פרומפט בעברית 🟢

**שם ומטרה:** להעמיד גרסה ראשונה ועובדת של הדף היחיד, שבה משתמש יכול לבחור פרומפט בעברית ולקרוא אותו כ-Markdown מעוצב.

**מה יש לממש:**
- הקמת React + TypeScript + Vite, התקנת `react-markdown` ו-`remark-gfm`, ושימוש ב-CSS רגיל.
- שלד ממשק ה-Desktop בהתאם ל-Wireframes ול-DESIGN: כותרת **„פרומפטים עבור פיתוח מונחה מפרט”**, לחצני השפה הגלויים, טור שבעת לחצני הפרומפטים מימין ואזור תוכן משמאל. בשלב זה הפעולה הפעילה היא בחירת פרומפט בעברית; החלפת שפה תמומש ב-Milestone 3.
- שמות שבעת הלחצנים והסדר שלהם כפי שנקבעו ב-PRD, מבלי לשנותם; מיפוי קבוע בין Prompt ID לבין קובץ `.md` מתאים. גם תוויות `.png` מפנות לקובצי Markdown.
- שילוב קובצי ה-Markdown הקיימים כ-Static Assets, עם נתיבים התואמים ל-`BASE_URL`; טעינת קובץ המקור והצגתו באמצעות `react-markdown` ו-`remark-gfm`.
- מצב פתיחה עם ההנחיה **„בחר פרומפט מהרשימה כדי להציג ולהעתיק אותו.”**; הדגשת הפרומפט הנבחר, החלפת תוכן בין לחצנים וחזרה לתחילת הפרומפט בגלילת הדף.
- מימוש פריסת Desktop וטיפוגרפיה, צבעים, מרווחים, מסגרות ויררכיית תוכן בהתאם ל-DESIGN ול-Style Guide. הטקסט נגלל עם **הדף כולו**, ללא Sticky Sidebar או גלילה פנימית של התצוגה.

**תוצר מצופה:** אתר מקומי שניתן לפתוח ב-Chrome או ב-Edge, לבחור בו אחד משבעת הפרומפטים בעברית ולקרוא את תוכנו המעוצב, ככל שקובצי המקור קיימים.

**Definition of Done:**
- `npm run dev` מפעיל אתר מקומי ו-`npm run build` מסתיים ללא שגיאות.
- הדף היחיד נפתח בעברית, RTL, עם הכותרת הנכונה, ההנחיה הנכונה ושבע התוויות בסדר הנדרש.
- לחיצה על כל אחד משבעת הלחצנים שיש עבורו מקור זמין מציגה את **קובץ ה-Markdown התואם**, כולל כותרות, רשימות וטבלאות לפי התוכן; אין יצירת תוכן חלופי.
- מעבר בין שני פרומפטים מחליף את התוכן, משאיר לחצן מודגש אחד לכל היותר ומחזיר את גלילת הדף לתחילת התוכן החדש.
- אזור התוכן ארוך ככל שנדרש, ואין גלילה פנימית או לחצנים Sticky.
- הפריסה והעיצוב תואמים למקורות, ללא דפים או פיצ'רים נוספים.

## Milestone 2 – העתקת Markdown אוטומטית וידנית 🟢

**שם ומטרה:** לאפשר למשתמש להעתיק פרומפט שלם בלחיצה או להעתיק ידנית את ה-Markdown המקורי, גם כאשר Clipboard API נכשל.

**מה יש לממש:**
- ניסיון `navigator.clipboard.writeText` בכל בחירת פרומפט, כולל לחיצה חוזרת על הפרומפט הנבחר; העתקת **טקסט המקור המקורי** ולא HTML מרונדר.
- שימוש בטעינה מוקדמת לזיכרון ככל שנדרש כדי להתחיל את ניסיון ההעתקה מתוך Click Handler, בהתאם ל-ARCHITECTURE; טיפול אמיתי ב-Promise, בלי להניח שההעתקה הצליחה.
- הודעת הצלחה או כישלון בעברית, בהתאם לתוצאה; במקרה של כישלון – הנחיה להעתקה ידנית.
- בתוך אותו אזור תוכן: תצוגת מקור Markdown ניתנת לסימון באמצעות `textarea` מסוג read-only, ללא גלילה פנימית, לצד התצוגה המרונדרת; סימון והעתקה מלאה או חלקית נעשים מתוך המקור.
- שמירה על יכולת קריאת הפרומפט גם אם ההעתקה האוטומטית נכשלה.

**תוצר מצופה:** בחירת פרומפט מציגה אותו ומנסה להעתיק אותו; המשתמש יכול גם לסמן את מקור ה-Markdown ולהעתיק ממנו כל טווח טקסט.

**Definition of Done:**
- בעת בחירת פרומפט טעון, ה-Clipboard מכיל את תוכן קובץ ה-`.md` כפי שהוא, לרבות תווי Markdown ושורות חדשות, כאשר הפעולה מורשית.
- לחיצה חוזרת על אותו לחצן מבצעת ניסיון העתקה נוסף.
- הודעת הצלחה מוצגת **רק** לאחר שהעתקה הצליחה בפועל; חסימת Clipboard או שגיאה מציגות הודעת כישלון והנחיה ידנית.
- ניתן לבצע `Ctrl+C` מתוך תצוגת המקור לקריאה בלבד, הן על מלוא התוכן והן על בחירה חלקית; הטקסט המתקבל שווה בדיוק לתווים שנבחרו במקור, כולל סימוני Markdown המצויים בטווח.
- תצוגת הפרומפט נשארת זמינה במקרה של כשל בהעתקה; אין גלילה פנימית באזור המקור.

## Milestone 3 – מעבר שפה ושמירת בחירה 🟢

**שם ומטרה:** לאפשר שימוש מלא באתר בעברית ובאנגלית, תוך שמירה על העדפת השפה מביקור לביקור.

**מה יש לממש:**
- הפעלת שני לחצני השפה הקבועים: **🇮🇱 „עברית”** ו-**🇺🇸 „English”**.
- כותרת, הנחיה והודעות מערכת בשפה שנבחרה; החלפת `lang`/`dir`, יישור וסידור העמודות: בעברית טור הפרומפטים מימין, ובאנגלית משמאל.
- מיפוי שבעת הפרומפטים ל-14 קובצי Markdown קיימים – שבעה בכל שפה – תוך שמירה על תוויות וסדר לחצני הפרומפטים בשתי השפות.
- איפוס הפרומפט הנבחר, ההדגשה, התוכן ומצב ההעתקה בעת שינוי שפה; אין להעתיק אוטומטית עקב מעבר השפה בלבד.
- שמירת `he` או `en` ב-`localStorage`, עם ברירת מחדל `he` אם אין ערך תקין או שהגישה ל-Storage חסומה.

**תוצר מצופה:** משתמש בוחר שפה, מקבל את התוכן ואת הממשק המתאימים לה, ובכניסה הבאה האתר נפתח בשפה ששמר, ככל שהדפדפן מאפשר.

**Definition of Done:**
- בביקור ראשון, ללא העדפה שמורה, הממשק בעברית עם `RTL` והכותרת **„פרומפטים עבור פיתוח מונחה מפרט”**.
- מעבר לאנגלית משנה את הכותרת ל-**“Spec-Driven Development Prompts”**, מגדיר `LTR`, מעביר את טור הפרומפטים לשמאל ומציג **“Select a prompt from the list to view and copy it.”**
- מעבר חזרה לעברית מחזיר את הכותרת, הכיווניות, היישור והסידור המקוריים.
- מעבר שפה מנקה בחירה, הדגשה, תוכן והודעת העתקה, ואינו מבצע העתקה אוטומטית.
- תוויות שבעת הלחצנים אינן משתנות; בכל שפה בחירה טוענת את קובץ ה-`.md` המקביל ומפעילה את יכולות ההעתקה שנבנו.
- רענון או ביקור חוזר משחזרים את השפה האחרונה שנבחרה; ערך Storage לא תקין או כשל גישה אינם שוברים את האתר וברירת המחדל היא עברית.

## Milestone 4 – שגיאות, מצבי קצה ובדיקת התאמה 🟢

**שם ומטרה:** להבטיח שהתנהגות הממשק אמינה גם בטעינה שנכשלה, בבחירות מהירות ובתוכן ארוך, ושכל הדרישות שנבנו פועלות ב-Chrome וב-Edge.

**מה יש לממש:**
- מצב טעינה וכשל לכל קובץ Markdown. כאשר קובץ חסר או `fetch` נכשל, מציגים הודעת שגיאה בשפה הפעילה; תוכן ישן אינו מוצג כאילו שייך לפרומפט החדש.
- שמירה על זמינות כל לחצני הפרומפטים האחרים לאחר כשל בקובץ מסוים.
- מניעת Race Conditions בהחלפות מהירות של פרומפטים או שפה, כך שתוצאה מאוחרת לא דורסת את הבחירה הנוכחית.
- טיפול עקבי במשוב Clipboard לאחר החלפת בחירה או שפה, כדי שהודעה ישנה לא תוצג עבור פרומפט אחר.
- בדיקת קריאות Markdown, טבלאות, טקסט משולב עברית/אנגלית, נגישות בסיסית של Buttons וסטטוס, ופריסה/מרווחים בהתאם ל-DESIGN.

**תוצר מצופה:** אתר מקומי שמכסה את כל מצבי התצוגה המוגדרים ב-PRD, לרבות הודעות שגיאה והתנהגות נכונה במקרי קצה.

**Definition of Done:**
- ניתן לדמות קובץ Markdown חסר או תשובת `fetch` שנכשלה: מוצגת הודעת שגיאה בשפה המתאימה, ללא תוכן ישן, וכל יתר הלחצנים ממשיכים לפעול.
- בחירה מהירה בין פרומפטים או החלפת שפה בזמן טעינה משאירות על המסך רק תוכן והודעות השייכים לבחירה ולשפה העדכניות.
- כשל ב-Clipboard אינו מונע קריאה או העתקה ידנית; לא מוצגת הודעת הצלחה מטעה.
- פרומפטים ארוכים נגללים עם הדף כולו; אין Scroll פנימי או Sidebar מוצמד.
- בדיקה ידנית בגרסאות Desktop של Chrome ושל Edge מאמתת בחירה, תצוגה, העתקה, שתי שפות, שמירת העדפה ומצבי שגיאה.
- נבדקו התאמה ל-PRD, ל-ARCHITECTURE ול-DESIGN, ללא תוספת פיצ'רים, דפים או שירותים שאינם נדרשים.

## Milestone 5 – GitHub ופריסה אוטומטית לאינטרנט ✅

**שם ומטרה:** להעמיד את האתר לשימוש ציבורי באמצעות GitHub Pages, עם Build ו-Deployment אוטומטיים לאחר Push ל-`main`.

**מה יש לממש:**
- ניהול הפרויקט ב-Git Repository ב-GitHub, כולל הקוד, `package-lock.json`, 14 קובצי Markdown קיימים ו-Workflow הפריסה.
- הגדרת Vite `base` בהתאם לסוג אתר GitHub Pages וכתובת ה-Repository, תוך שימוש ב-`import.meta.env.BASE_URL` עבור נכסי ה-Markdown.
- GitHub Actions שמבצע `npm ci`, בדיקת Build ויצירת `dist`, העלאת Artifact ו-Deployment ל-GitHub Pages על בסיס Push ל-`main`.
- בדיקה של האתר שפורסם ב-HTTPS, לרבות טעינת נכסי Markdown, שימוש ב-Clipboard, פריסה, רענון ושמירת שפה ב-Desktop Chrome ו-Edge.

**תוצר מצופה:** אתר ציבורי מתפקד ב-GitHub Pages, המתעדכן אוטומטית כאשר מתבצע Push לענף `main`.

**Definition of Done:**
- ה-Repository ב-GitHub מכיל את קוד המקור ואת כל קובצי ה-Markdown הזמינים שנדרשים להפעלה מלאה; לפני אישור הפריסה הסופית נמצאים בו **כל 14 קובצי המקור המקוריים**.
- GitHub Actions מבצע Build ו-Deployment מוצלחים, ללא פריסה ידנית של קבצי `dist`.
- כתובת GitHub Pages נפתחת ב-HTTPS, והעמוד נטען לאחר רענון ישיר.
- כל 14 קובצי Markdown נטענים מהנתיבים הנכונים באתר המפורסם (ללא שגיאות Base Path), ושבעת הלחצנים פועלים בשתי השפות.
- נבדקו באתר המפורסם תצוגת Markdown, העתקה אוטומטית, העתקה ידנית, RTL/LTR, שמירת שפה והתנהגות במצב כשל.
- Push נוסף ל-`main` מפעיל Workflow ומפרסם את הגרסה המעודכנת אוטומטית.

## Development Execution Rules – הנחיות מחייבות ל-AI המבצע את הפיתוח

1. יש לממש את ה-Milestones **לפי הסדר** שבו הם מוגדרים במסמך. כל Milestone מתבסס על התוצרים שאושרו לפניו.
2. בסיום **כל** Milestone יש לעצור את הפיתוח ולהציג למשתמש: מה מומש, כיצד ניתן להפעיל או לצפות בתוצר, ואילו בדיקות בוצעו ומה תוצאתן מול **כל סעיף** ב-Definition of Done.
3. אם תנאי השלמה אינו מתקיים, יש לציין זאת במפורש ולהמשיך בטיפול באותו Milestone; אין להציגו כמאושר או להסתיר בדיקות שלא ניתן היה לבצע.
4. **אין להתחיל את ה-Milestone הבא ללא אישור מפורש של המשתמש**, גם אם כל הבדיקות עברו בהצלחה.
5. אין להוסיף פיצ'רים או לשנות את דרישות ה-PRD, הארכיטקטורה או העיצוב ללא אישור המשתמש. אין להמציא את תוכן 14 קובצי המקור החסרים.
