Based on the PRD document, the Wireframes image, the Style Guide image, and the Mockups image we created, generate a document named **DESIGN.md** describing the application's design.

The final document must be written in English. However, all user-facing UI text, such as headings, buttons, messages, and labels, must use the interface language defined in the PRD, regardless of the document language.

**Information Sources:**
- **PRD:** The source for product requirements, screen behavior, and UX constraints that must be considered in the design, without the need to document them again.
- **Wireframes:** The source for screen structure, layout, and UI components.
- **Style Guide:** The source for the design language, colors, typography, and component styling.
- **Mockups:** The source for the final visual appearance of the screens.

**Images in the Document:**

Embed the three images in appropriate locations within the document using Markdown image syntax, with relative paths assuming that the images are located in the same directory as the document:

- `wireframes.png`
- `style-guide.png`
- `mockups.png`

**The document must include two main sections:**

### 1. Screens – Application Screens

Describe all the main screens of the application. For each screen, briefly specify:
- **Screen Purpose:** What the user is expected to do or achieve on the screen.
- **Structure and Content:** The main UI components, such as buttons, input fields, forms, lists, text, menus, and content areas, and how they are arranged.
- **Actions and Navigation:** The actions the user can perform and the transitions to other screens.

At the end of this section, briefly describe the overall navigation structure between the screens.

### 2. Style Guide – Visual Design Language

Describe the application's visual design language based on the Style Guide and Mockups, including:
- **Color Palette:** Primary colors and HEX codes, where defined in the sources.
- **Typography:** Fonts, text hierarchy, and recommended font sizes.
- **UI Style:** Styling of buttons, input fields, cards, menus, icons, and other interface components.
- **Visual Style:** Shapes, corners, borders, shadows, spacing, alignment, layout, image or illustration styles, and the overall visual atmosphere.
- **Language and Directionality:** Interface language, RTL / LTR directionality, and component alignment, according to the PRD.

**Additional Guidelines:**

- Base the document on the source materials and images, ensuring consistency between them and alignment with the PRD requirements.
- Focus on describing the design implementation, without repeating product requirements or UX principles already documented in the PRD.
- Do not introduce screens, features, or behaviors that have not been defined in the source materials.
- Do not invent design details that are not present in the sources. If a visual detail is unclear, refer to the Style Guide and PRD, and do not present guesses as facts.
- Write in clear, simple, and concise language, while providing enough detail for an AI system to use the document as a foundation for implementing the user interface.
