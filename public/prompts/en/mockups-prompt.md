Based on the **Wireframes** and **Style Guide** images we created, generate a single **Mockups** image named **mockups.png** for the application's screens.

Transform the Wireframes into visually designed, detailed, and aesthetically appealing screens, while maintaining full consistency between the structure of the Wireframes and the visual design language of the Style Guide.

**Before creating the image:**

- Count the screens in the Wireframes image, write a numbered list of their names and their total count in your reply, and then immediately create the image, without waiting for approval.
- The Mockups image must contain **exactly the screens in the list**, no more and no fewer. The list appears in the text of your reply only, not inside the image.

**Guidelines:**

- Use the **Wireframes** as the foundation for the screen structure, layout, content hierarchy, UI components, and number of screens.
- Use the **Style Guide** as the foundation for colors, typography, icons, component styling, and the overall visual design language.
- Preserve the **number of screens**, **screen order**, **structure of each screen**, **main UI components**, and **main content** exactly as they appear in the Wireframes.
- Show each screen **exactly once**, in the same state, in the same language, and with the same messages as in the Wireframes. Do not add versions, variations, additional states (for example success, error, or loading messages), or another-language version of the same screen.
- Display **the screen name above each screen**, identical to the name shown above it in the Wireframes and to the name in the list. Preserve the interface language as defined in the Wireframes and PRD.
- Maintain the appropriate language direction, alignment, and interface language, including **RTL / LTR**, according to the PRD.
- Ensure **complete visual consistency** across all screens.
- If there is a conflict between the Wireframes and the Style Guide, prioritize the structure and content of the Wireframes and the visual design language of the Style Guide.
- Do not add new screens, new features, or significant UI components that do not appear in the Wireframes, and do not change the product's main user flow.
- You may visually enhance the screens and add design details, but **do not change the functional meaning of the screens**.
- Present all screens together in a single image, in a clear, organized, and readable manner. **The number of screens determines the layout, not the other way around:** do not add screens, copies, or variations to fill or balance the image; empty space around the screens is acceptable.
- Maintain an **overall layout consistent with the Wireframes image**, so that each screen in the Wireframes is represented by a corresponding Mockup in the same order, with matching dimensions and proportions as closely as possible.
- Each screen in the Mockups image must represent its corresponding screen in the Wireframes, preserving the same essential UI content while applying a higher level of visual design and detail.

**Goal:**

To illustrate how the application will look after the visual design stage, while fully preserving the structure and logic of the Wireframes and the visual design language of the Style Guide.

**Required Output:**

- One image only, named **mockups.png**, containing exactly the screens in the Wireframes, each screen once.
